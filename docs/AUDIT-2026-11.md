# PMAS audit, November 2026

Three audit cycles. Cycle 1 maps the failures only. Cycles 2 and 3 search and fix.
Each finding has an ID. The prefix shows the area: A = import, B = analytics and EVM, C = CRUD and admin, D = frontend.
Severity: HIGH = wrong numbers, data loss, a crash or a feature that does not work. MEDIUM = wrong behavior or bad validation. LOW = polish.

## Cycle 3 - review, journeys, invariants and leftovers

Four engineers worked in parallel. One reviewed the cycle 2 changes. One drove complete user journeys by role in a browser. One tested data invariants with generated data and fuzzing. One fixed leftovers, documentation drift and operations.
Result after the merge: 995 backend tests (1 skipped without the `sqlite3` program), 46 Vitest tests, 75 Playwright tests.

## Product decisions (after cycle 3)

| ID | Decision | Result |
|----|----------|--------|
| A1 | Sum rows of the same day with different hours; keep discarding exact duplicates | Done |
| A4b | An empty whitelist means access to all, also on the import | Done |
| B1, B2 | A date range is the record date everywhere; forecast, What-If and Monte Carlo ignore it | Done |
| C10 | Only an administrator creates, activates or deletes a baseline; audit entries added | Done |

Still open (not decided): A10 (ambiguous dates such as 01/13/2026 are guessed), D7 (server messages are Portuguese in the English UI), SVG logo uploads, an import into a closed cycle by an administrator (allowed today), number format in Portuguese (`208.0h` against `208,0h`), the Projects tab sends one request per project for baselines, the upload response can carry thousands of warning lines.
Final result: 1,025 backend tests (1 skipped), 46 Vitest tests, 78 Playwright tests.
